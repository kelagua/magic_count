# 农资店赊账/结清业务手册 (Credit & Settlement Business Manual)

本档定义 magic_count (LiteNote) 系统中赊账与结清业务的完整逻辑、状态流转和数据规范，确保商家能准确理解每种状态在系统中的含义。

---

## 1. 业务概述

农资店的经营模式中，**赊账** 是最常见的交易方式之一。农民在播种季节赊购种子、化肥、农药，等到秋收后再还款。LiteNote 系统针对这一场景，提供了从赊账记录到批量结清的完整业务流程。

### 核心业务场景
- 🌱 **春耕赊账**：农民赊购种子、底肥、农药
- 🧪 **追肥赊账**：作物生长期间赊购追肥、叶面肥
- 💰 **秋收回款**：秋收后农民还款结清
- 🔄 **部分还款**：农民先还一部分，剩余继续挂账
- 📊 **对账统计**：商家查看各客户欠款余额和回款情况

## 2. 状态流转 (State Machine)

```
                    ┌──────────────┐
                    │   赊账发生    │
                    │  (Credit)    │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │  未结清       │
                    │ (Unsettled)  │
                    │ isSettled=false │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
     ┌──────────────┐ ┌──────────┐ ┌──────────────┐
     │  部分还款     │ │ 全额还款  │ │ 继续赊账     │
     │ (Partial)    │ │ (Full)   │ │ (More Credit)│
     └──────┬───────┘ └────┬─────┘ └──────┬───────┘
            │              │              │
            │              ▼              │
            │       ┌──────────────┐      │
            │       │  已结清       │      │
            │       │ (Settled)    │      │
            │       │ isSettled=true│     │
            │       └──────────────┘      │
            │                             │
            └─────────────────────────────┘
              （仍为 Unsettled，余额减少）
```

### 状态说明

| 状态 | 字段值 | 含义 |
|------|--------|------|
| **未结清 (Unsettled)** | `isSettled = false` | 赊账尚未还清，仍挂账 |
| **已结清 (Settled)** | `isSettled = true` | 赊账已全额还清 |

## 3. 数据项定义 (Data Fields)

### 3.1 赊账记录 (Credit Bill)

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | String | ✅ | 固定为 `"credit"` |
| `amount` | Decimal | ✅ | 赊账金额（正数） |
| `customerId` | String (UUID) | ✅ | 关联客户 ID |
| `description` | String | ❌ | 赊账描述（如"三袋复合肥"） |
| `categoryId` | Int | ❌ | 商品分类 ID |
| `date` | Date | ✅ | **赊账时间**（商品卖出的精确时间） |
| `paymentMethod` | Enum | ✅ | 固定为 `"CREDIT"` |
| `isSettled` | Boolean | ✅ | 默认 `false` |
| `settledAt` | DateTime | ❌ | 结算时间（结清时填写） |
| `tags` | String[] | ❌ | 标签（如 ["化肥", "春耕"]） |
| `notes` | String | ❌ | 备注 |

### 3.2 客户档案 (Customer)

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | String | ✅ | 农户姓名 |
| `phone` | String | ❌ | 联系方式 |
| `address` | String | ❌ | 地址 |
| `notes` | String | ❌ | 备注 |
| `balance` | Decimal | ✅ | 累计欠款余额（系统自动计算） |

### 3.3 支付方式 (PaymentMethod)

| 值 | 含义 | 使用场景 |
|----|------|----------|
| `CREDIT` | 赊账 | 赊账发生时 |
| `WECHAT` | 微信支付 | 还款时 |
| `ALIPAY` | 支付宝 | 还款时 |
| `CASH` | 现金 | 还款时 |

## 4. 业务流程 (Business Workflows)

### 4.1 赊账流程

```
商家操作 → 选择客户 → 输入商品/金额 → 确认赊账
```

**详细步骤**：
1. 商家通过 AI 语音/文字/拍照输入赊账信息
2. AI 识别客户名、商品、金额
3. 系统创建 `type=credit` 的账单，`isSettled=false`
4. **必须记录当前的精确赊账时间**（`date` 字段）
5. 自动更新客户 `balance`（累加欠款）

**AI 交互示例**：
- "老王赊了三袋 15-15-15 的复合肥" → AI 调用 `create_bills` 创建赊账记录
- "李大爷拿了两袋尿素，240 块，先记账上" → AI 创建赊账记录

### 4.2 还款/结清流程

```
商家操作 → 选择客户 → 选择待结清账单 → 选择支付方式 → 确认结清
```

**详细步骤**：
1. 商家输入还款信息（如"老王微信还了 500"）
2. AI 识别客户名、金额、支付方式
3. 系统更新账单状态：`isSettled=true`，记录 `settledAt` 和 `paymentMethod`
4. **必须记录精确的结算时间**（`settledAt` 字段）
5. 自动更新客户 `balance`（减少欠款）

### 4.3 批量结清流程

```
商家操作 → 选择客户 → 查看未结清列表 → 多选账单 → 选择支付方式 → 批量结清
```

**详细步骤**：
1. 商家在客户详情页或未结清列表中选择多笔赊账
2. 选择支付方式（微信/支付宝/现金）
3. 调用 `POST /bills/settle-batch` API
4. 系统批量更新所有选中账单的状态
5. 自动更新客户 `balance`

**AI 交互示例**：
- "把老王去年的账都结了" → AI 调用 `batchSettleBills`
- "李大爷现金还了 200，剩下的以后再说" → AI 部分还款处理

### 4.4 部分还款处理

当还款金额小于总欠款时：
1. 创建一笔 `type=income` 的回款记录
2. 原赊账记录保持 `isSettled=false`
3. 客户 `balance` 相应减少
4. 剩余欠款继续挂账

## 5. 客户余额对账逻辑 (Balance Reconciliation)

每笔 Bill 的增删改都应触发 `Customer.balance` 的同步更新：

| 操作 | 对 balance 的影响 |
|------|-------------------|
| 新增赊账 (`type=credit`) | `balance += amount` |
| 结清赊账 (`isSettled: false → true`) | `balance -= amount` |
| 删除赊账 (`type=credit`, 未结清) | `balance -= amount` |
| 删除赊账 (`type=credit`, 已结清) | 无影响（已还清） |
| 修改赊账金额 | `balance += (新金额 - 旧金额)` |

## 6. 时间语义规范 (Time Semantics)

### 赊账时间 (Credit Date)
- **字段**：`date`
- **含义**：商品卖出的精确时间
- **规则**：
  - 如用户明确指定时间，使用指定时间
  - 如用户说"刚才"、"今天"，使用当前时间
  - 如用户说"昨天"、"上周"，AI 需解析为对应日期

### 结算时间 (Settlement Date)
- **字段**：`settledAt`
- **含义**：回款的精确时间
- **规则**：
  - 默认使用当前时间
  - 如用户说"昨天还的"，解析为昨天的时间

### 时间解析参考

| 口语表达 | 转换规则 |
|----------|----------|
| "刚才" | 当前时间前推 10 分钟 |
| "今天" | 当日日期 |
| "昨天" | 前一日日期 |
| "上周五" | 上周五对应日期 |
| "上个月" | 上月 1 日 |

## 7. 常见问题 (FAQ)

**Q: 一笔赊账可以部分还款多次吗？**
A: 可以。每次部分还款创建一笔 `type=income` 的回款记录，原赊账保持未结清状态，直到全额还清。

**Q: 客户余额为负数是什么意思？**
A: 余额为负表示客户多还了钱（预付款），正常情况下余额应 ≥ 0。

**Q: 误删了赊账记录怎么办？**
A: 目前删除操作不可逆（TD-003），建议操作前确认。后续计划增加软删除和回收站功能。

**Q: AI 识别客户名不准确怎么办？**
A: AI 会列出模糊匹配的候选客户，由用户确认。如无匹配，会提示新建客户档案。
